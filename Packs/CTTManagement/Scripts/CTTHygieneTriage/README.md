Triage step of the `CTT - Hygiene - Notify Owner` playbook. It reads the current hygiene issue, finds the owner from the `[owner: ...]` marker that every CTT rule and the inventory check write into the description, looks the owner up in the CTT registry (name, role, Slack ID), quotes the guideline from the `CTT - Guidelines Index` list, and decides whether to assign the issue and whether to DM the owner. DMs follow `notify.mode` (`off`, `admins_only`, `all`) and `notify.max_dms_per_owner_per_day` in `CTT - Config`.

It also flags duplicates (`CTT.Triage.duplicate_of`): an older open issue about the same endpoint, user or object, or one marked a false positive in the last `notify.false_positive_days` days (default 30). The daily rules (CTT-LAB-01, CTT-GEN-01) raise a finding again once their one-day suppression ends; the playbook closes such a duplicate as Duplicate Issue without a DM.
