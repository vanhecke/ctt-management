#### Playbooks

##### CTT - Hygiene - Notify Owner

The playbook now runs in this order:

- **Duplicate?** The new `CTTHygieneDuplicateCheck` looks for another open issue about the same endpoint, user or object, or one marked a false positive in the last `notify.false_positive_days` days (the daily rules raised the same finding again every day). Such an issue is closed as Duplicate Issue.
- **Already fixed?** The guideline's automatic check runs before anyone is assigned or notified; a fixed issue is closed with a close note.
- Otherwise the issue is assigned to its owner and set to In Progress, and the new **CTT - Hygiene - Ask Owner** sub-playbook runs (repeated until the owner's answer closes the issue) next to an hourly watch (a scheduled command) that closes the issue once the check sees it fixed.

When the owner's answer or the hourly watch closes the issue, the owner gets a thank-you DM quoting the close note first. The issue is always closed by the last task of a branch, with a close note.

##### New: CTT - Hygiene - Ask Owner

One question round per run: asks the owner "Did you fix it?" by Generated link and sends the Slack DM with the answers as buttons Mark as Fixed / Mark as False Positive / View Issue (`notify.buttons`). Mark as Fixed runs the fix check: a verified fix, or a guideline without a check, closes the issue; otherwise the round notes what is still wrong, and Notify Owner runs Ask Owner again (the task's loop, at most 10 rounds) with a DM that starts with it. Mark as False Positive closes the issue as False Positive and tells the CTT channel. When a DM can't go out (daily limit, `notify.mode`, allowlist, no Slack ID) only the DM is skipped.

##### New: CTT - Hygiene - Fix Check

Runs `CTTHygieneFixCheck` every hour (job of the same name).

##### New: CTT - Hygiene - Reminders

Runs `CTTHygieneFixCheck remind=true` every day at 10:00 SGT (job of the same name).

#### Correlation Rules

##### CTT - Hygiene - Object created without owner tag

Also checks new data collectors (HTTP collectors and other data collection, audit entries "<type> Data Collection for <name> created"). Firewall device collection is skipped (its name is the device serial).

##### CTT - Hygiene - Endpoint outside owner's lab range

A lab octet now covers `172.16.<octet>.0/24` as well as `10.<octet>.0.0/16` (CTT-LAB-01). The endpoint field is `lab_ip` (was `ip10`).

#### Scripts

##### New: CTTHygieneFixCheck

Checks open CTT hygiene issues from the correlation rules and resolves the fixed ones with a close note saying why: GEN-01 registry entries, TAG-01/TAG-04 renamed or deleted objects (TAG-01: or a playbook, script or job with the owner's tag in its Tags field), TAG-02 policy scopes, OOTB-01 re-attached built-in playbooks and scripts, LAB-01 endpoint ranges. Also handles the owner's Mark as Fixed and Mark as False Positive answers and sends the daily digests. Closes hygiene cases once all their issues are resolved (a resolved issue left its case open).

##### New: CTTHygieneDuplicateCheck

Finds another open CTT hygiene issue about the same endpoint, user or object, or one marked a false positive in the last `notify.false_positive_days` days (default 30), for the Notify Owner playbook's first step.

##### New: CTTHygieneAskLinks

Returns the newest answer links of the Notify Owner question for the DM.

##### CTTHygieneSendDM

New arguments `fixed_url`, `not_violation_url`, `buttons` and `note`, and `closed` / `close_reason` / `close_note` for the thank-you DM when an issue is closed (it doesn't count toward the daily DM limit).

##### CTTHygieneTriage

New output `CTT.Triage.buttons` (`notify.buttons` in `CTT - Config`). The LAB-01 fix advice names both lab ranges; the TAG-01 advice for a playbook, script or job offers the Tags field. Inventory DMs put items of one kind with the same finding on one line and say once why the owner was chosen.

##### CTTInventoryCheck

CTT-TAG-01: a playbook, script or job with a registered tag in its Tags field needs no name prefix; that tag names its owner.

Also inventories data collectors (HTTP collectors): those created in the last year and neither edited nor deleted since, from the audit log (no API lists them). Skips the platform's `testmodule` instance and the user hook scripts `CommonServerUserPython`, `CommonServerUserPowerShell` and `CommonUserServer`.

Also checks custom policy profiles (name prefix), the policy rules in use (name prefix, and a scope that targets one of the owner's tags rather than endpoint names, CTT-TAG-02) and installed endpoints without a registered tag (CTT-LAB-02, now an active guideline; one issue per likely owner).

##### CTTCaseHousekeeping

Lab addresses in `172.16.<octet>.0/24` count for the owner's lab octet, like `10.<octet>.0.0/16`.

##### CTTMarketplaceUpdates

Review issues that are no longer needed (the pack reached the target version, or a newer target replaced it) are now resolved as Resolved - Other, and their case is closed once all its issues are resolved. They were resolved as Resolved - Fixed, which tenants without that license refuse, so they stayed open and every run reported `resolve_failed`. The run summary counts review issues that could not be closed.

##### CTTRegistryLookup

Accepts `172.16.<octet>.x` addresses and shows both lab ranges of an owner.

##### CTTEnsureJobs

Jobs now get `category: job`, `parent` (their own id), `endingType` and an owner, as the web UI sets them. Without these the scheduler dropped every run silently, so no CTT job had run its playbook. New argument `owner` (default: the job's owner, else the user running the script). Existing jobs are repaired on the next run; a job disabled on the tenant stays disabled.

##### CTTTenantStatus

The HYGIENE section shows closes by way, median time to fix per guideline, top fixers and the oldest open issue.

#### Agents

##### CTT Assistant

New knowledge document CTT-Assistant (what the agent can do, its approvals and limits), so it can answer "what can you do?". The hygiene skill and CTTMyFootprintAction list the object types the inventory check now covers.

#### Integrations

##### CTT Slack Webhook

New action `msg_person_health_issue`: a DM with the buttons Mark as Fixed (`fixed_url`), Mark as False Positive (`not_violation_url`) and View Issue (`issue_url`). Every call now sends the three button inputs (`-` when unused), as the workflow's webhook declares them.

#### Actions

##### New: CTTHygieneConfirmFixAction

The CTT Assistant records a fix the user reports and runs the fix check (with the user's approval).

#### Lists

##### CTT - Config

New `notify.buttons` (default `true`) and `notify.false_positive_days` (default 30). `notify.mode` is now `all`: hygiene DMs and digests go to every owner in the registry sheet with a Slack ID.

##### CTT - Jobs

Adds the `CTT - Hygiene - Fix Check` and `CTT - Hygiene - Reminders` jobs, and the job fields the scheduler needs to run them. The job playbooks now close their run in their last task. Run `!CTTEnsureJobs remove_obsolete=true` after upgrading.
